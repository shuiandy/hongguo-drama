## 方法

- 页面通过 CDP（端口 9333）驱动；主进程窗口属性通过 SIGUSR1 打开的 Node inspector 读取，仅作用于测试进程。
- 窗口外观用 `screencapture -o -l <窗口号>` 截取，圆角以截图四角 alpha=0 判定。
- 首轮未使用物理鼠标或键盘，「移出窗口」用主进程 `setPosition` 把窗口挪离真实光标来模拟；拖动、缩放和真实悬停在补测中用物理鼠标完成（见下文）。

## 修复

1. 竖屏播放区高度：`.player-stage` 的 `height: 100%` 依赖 `.player-floating-slot`，但后者高度为 auto。未播放时播放区塌成约 150px，播放后被 9:16 视频撑到 1059px（窗口可视 892px），控制条落在窗口外；`main-content` 为 `overflow: hidden`，还会保留横屏时的滚动位置。main 分支同样存在此问题，不是本 PR 引入。修复：桌面竖屏（不含 Android）网格 `align-items: stretch`，`.player-floating-slot` 取 `height: 100%`。修复后播放区约 585px，完整位于窗口内，竖屏选集展开、横屏及小窗均已回归。
2. 竖屏进入小窗留边：`.layout-portrait.player-focused .main-content[data-page="player"]` 的 8/12px 内边距优先级高于小窗的 `padding: 0`，导致四周出现深色边框。提高小窗选择器优先级后，从竖屏和横屏进入都是满窗。

3. 顶部浮层在真实指针下消失：macOS 不向 `-webkit-app-region: drag` 区域发送鼠标事件，CSS `:hover` 恰好在指针移到浮层空白处时失效。小窗：原生控制器在指针离开时已隐藏整个窗口，因此浮层改为小窗可见时常显。悬浮窗：主进程每 100ms 比较原生光标与窗口位置，给页面 `body` 写 `data-pointer`，浮层据此显示。

`check-player-resume`、`check-stealth-window`、`check-floating-player-window`、`check-floating-player-host`、`check-ui-state` 均通过。
